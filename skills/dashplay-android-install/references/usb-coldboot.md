# 已选择默认 USB 应用，冷启动仍弹授权

此排查仅适用于安卓盒子的有线 CarPlay，以及用户明确启用的 USB 上网；安卓手机仅支持无线 CarPlay，不使用本页恢复手机有线连接。

先区分默认关联没保存、权限条件缺失、应用被禁用，以及 USB 比用户解锁更早到达。不要先清数据、忽略车辆或反复拔线。

## 排查 USB 比用户解锁更早到达的情况

保持 iPhone 插线冷启动，比较 USB 枚举与 RUNNING_UNLOCKED 的时间。即使 ROM 没有启用存储加密，也可能有用户未解锁阶段；不能按型号推断事件顺序。

如果默认 USB 关联存在，但 APK 的 `UsbAttachActivity` 没有 `directBootAware`，系统可能在这一阶段匹配不到处理 Activity，无法自动授予访问权；随后应用启动再请求权限，就会出现 USB 弹窗。需同时核实默认关联、必要权限和组件启用，不能直接归因于用户忘了勾选默认。

应用侧应满足：

- 仅 USB 接收 Activity 标记 `android:directBootAware="true"`，让系统在未解锁时能匹配保存的默认应用并授予 USB 权限。
- Activity 在 API 24+ 检查 `UserManager.isUserUnlocked`；未解锁立即结束，不访问普通偏好、身份或启动接收服务。
- 正常 `BOOT_COMPLETED` 后再读取设置、启动服务。没有把身份搬到设备保护存储，也没有修改 ROM 的 USB 权限文件。

修复后分别做 ADB 整机重启与真实断电测试，确认零点击恢复 CarPlay、持续收视频、借网正常且隧道不累积。单个设备通过不能推广为所有 ROM 通过；已有默认授权时的成功，也不等于首次安装无需授权。盒子模式还要核实前台为 MainActivity，手机模式保留后台启动。

## 排查顺序

1. 记录实际包和 ROM。确认 USB handler 启用、默认应用仍是 DashPlay、首次必要权限已完成。不要打印 iPhone 序列号或完整 USB 描述。
2. 比较 USB attach、用户解锁、应用启动和授权弹窗的日志时间。完整日志只留私有。先核实事件顺序再判断是否此问题。
3. 开发环境可运行 `android/scripts/check-usb-boot.sh 25`：检查 Direct Boot 组件解析及开机启动策略。它使用隔离模拟器，不用于改真实用户权限。源码构建需先生成 app/debug 和 androidTest APK。
4. 真机用包含修复的 APK 覆盖升级，核对实际已安装包，并保留既有配置；不通过写系统 USB XML 来伪造保存成功。
5. 重做真实断电测试，整个过程仅观察。如果仍弹窗，采集新证据；该次失败不得以 ADB 补点后能用改记成功。

应用自启与 USB 默认授权是两个环节。只增加启动服务、手工启动 Activity、延迟请求权限，都不能代替解决系统初次枚举时的默认关联匹配。
