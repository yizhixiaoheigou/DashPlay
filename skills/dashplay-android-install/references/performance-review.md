# 安装后约半小时性能验收与优化

首次配置和零点击启动通过后，帮助用户在电脑浏览器实际使用约半小时。AI 持续采集、分析并处理问题；不能只让用户自行观察，或者只给一张问题清单。此流程按当前设备的证据工作，不依赖型号名单。

## 建立基线与使用场景

- 核实实际 APK 摘要/软件版本、ROM、网络拓扑、浏览器、窗口大小与 DPR、编码、帧率、UI 大小及上报物理尺寸，记录时间基准。电脑浏览器结果不能代替真实车机结果。
- 前几分钟先观察空闲、首次打开页面和接入手机；随后滑动、切换页面、播放音乐、导航播报；再观察持续运行。窗口固定时与手动调整窗口时分开记录。
- 与用户约定开始时间。需要其操作时说明一个具体动作，AI 同时看日志。用户报告卡顿时优先捕获当时证据，不先重启、刷新、拔线或忽略车辆。
- 约半小时是目标使用窗口，不是后台预约。记录实际持续多久；用户中途停止或设备离线时如实标记，不能把已启动采样当作测试完成。长时间运行保持简短进度说明。

## 同时看哪些证据

| 环节 | 观察项与判读 |
| --- | --- |
| 浏览器 | 解码时间、队列、帧率、画面延迟、窗口/可视区、可见性、重连原因。静止画面低帧率、隐藏页面停止绘制不能单独算性能故障 |
| 接收端 | 实际会话、视频收发、序号缺口、丢帧、触控转发、首次画面和重连耗时；区分真实断线和应用主动协商 |
| 系统 | CPU 时间差、内存趋势、交换/低内存杀进程、温度及频率；与空闲和操作时对照，不能只看一张 top 截图 |
| 资源 | 线程、文件描述符、TUN、USB 通道数量是否随重连增加 |
| 网络 | 盒子到浏览器的延迟与吞吐、USB 链路及借网实际路径；区分局域网卡顿与手机外网慢 |
| ROM/预装软件 | 异常后台进程、循环创建子进程、监听不存在的硬件、日志刷屏、反复拉起应用；名称或“预装”本身不是禁用依据 |

使用现有诊断接口和已授权 ADB，低频采样，避免采样本身制造负载。原始日志私有保存；报告只保留必要指标，不暴露身份、token、密码、设备序列号或用户内容。

## 帧率正常但拖动不跟手

先固定一个观看窗口，并关闭诊断窗口的自动适配，核对前后共享流参数没有变化。区分鼠标拖动、触摸屏手势和滚轮；用相同页面、轨迹与参数比较不同接收端。

- 核对按下、移动、松开的真实发送序列，尤其小幅拖动在松开前的最后位置；平均 FPS 正常不能证明输入完整。发送返回耗时也不等于 iPhone 已处理或新画面已显示。
- 在已截图确认的应用列表空白处比较几档拖动距离，测按住时的实际画面位移。重协商可能返回另一页面，每次重新核对；不把原坐标直接用于导航、电话、消息或媒体页面。
- 若画面像先扣去一段距离再跟随，分别对比分辨率与 UI 大小/物理尺寸上报，检查手势门槛是否随其变化。保持其他参数不变，结束恢复原值；不要把某次测出的像素或毫米数固化为所有设备的阈值，也不要直接放大触控坐标来掩盖原因。
- 用户不在场时，可先做静态连接与资源观察；记录它的限制，不能代替半小时连续操作体验。换装新 APK 后，旧包的长测结果保留在旧包名下。

## 根据证据完成优化

1. 将用户反馈与同时间段日志对应，先分清响应慢、视频不连贯、页面崩溃、CarPlay 重连、系统资源不足。分别写明已确认原因和仍待验证的推测。
2. 每次只调整一个因素，先保存原配置/文件及恢复方法，做可恢复的对照。例如短暂暂停已明确异常的进程验证 CPU 来源，观察结束恢复；不能大批杀进程或按网上名单卸载 App。
3. 对应用问题修复应用：重复重连、等待过长、资源泄漏、自动画质误判不能用反复拔线或永久降画质掩盖。浏览器未知能力不等于性能不足；已经稳定解码的画面不应无故降级。
4. 确有解码或网络瓶颈时，再选择有证据支持的编码、帧率、分辨率或网络调整。说明对清晰度、延迟的影响，并与调整前同一使用场景对照。
5. 对 ROM/预装软件问题，定位实际启动入口、设备节点和失败路径，准备该设备专用的最小改动。修改系统文件、禁用系统组件或持久后台配置须遵守当前用户授权；保留必要硬件功能、文件权限和恢复路径。不要以关闭系统安全保护换取安装成功。
6. 修改后重测触发问题的操作；运行足够长观察效果和副作用。涉及启动或持久配置时另做重启/断电验收，检查自启、USB/VPN 默认授权、CarPlay 和借网仍正常。

## 交付

告诉用户实际测试时长、完成的场景、发现的问题、采取的优化、前后指标和恢复办法。把未复现的问题或等待用户操作的项目明确列出。新设备只复用分析方法，不能照搬别的设备的系统补丁。
