# DashPlay 安卓安装与首次设置

访问地址提示：安卓 HTTP 与 HTTPS 共用网页端口，默认 18743，自定义值以 App 显示为准。每次指引用户输入或打开地址，都明确提醒“请保留完整的 `http://` 或 `https://` 前缀，不要省略或替换”。复制和二维码须包含协议前缀。管理页面始终用 HTTP，不依赖证书或 HTTP 画面开关；RTC/JPEG 回退不更换端口。旧默认 8080/8081 升级为 18743；旧自定义 HTTP 端口保留为统一端口。

在现有 Android 上工作。先读 [逐题分支规则](references/capability-routing.md)，按其中的 Q1–Q16 引导；它是网络与能力关系的唯一规则，不另外创造简化结论。用户只要求梳理/修改文档时，不启动装机或真机验收。

## 交互方式

- **一次一个问题，答案决定下一题。** 当前路径不涉及的 Root、DNS、无线参数不问。可以自动观察的系统条件先观察，不让用户猜硬件/API/权限。
- 每题说明它决定什么；失败说明“缺什么 → 为什么影响当前功能 → 能改选什么”。停在缺失条件，不把后面所有问题一口气发给用户，不用“保存成功”代替功能可用。
- 返回更改上游答案时重新判断下游，保留凭据草稿和明确偏好，不静默切换连接模式。允许保存草稿，未准备好不开始验收。
- **只告知需要现成的安装入口、ADB 或 App Root 等能力，不指导刷机、解锁、获取 ADB、获取 Root、修改 su 权限或系统启动校验。** 用户自行寻找教程准备；普通路径不强求这些能力。
- 身份只提示：**本软件不附带 CarPlay 身份，请自行导入**。不提供来源或第三方安装包引导，不复制身份、密码、私钥和 token 到聊天/报告/日志。
- iPhone、车机的连接、切换、画面和听音由用户操作；AI 只检查已授权的日志与状态。通话测试单独由用户决定。

## 确认已有入口和安装包

安卓手机和盒子使用同一 APK，但安卓手机仅支持无线 CarPlay；安卓盒子保留有线、无线与自动选择。不要为绕过限制而将安卓手机标成盒子。手机优先自行安装；盒子先确认屏幕/遥控器、已运行的同网浏览器管理，或已有授权 ADB。当前管理页 `/manage` 不要求管理密钥，未导入身份也可进入；它仍不能代替 Android 的 USB/VPN/Root 系统授权。App 未安装/启动或根本没连网时，不承诺能凭空通过网页初设。

- 从 [DashPlay 发布列表](https://github.com/yizhixiaoheigou/DashPlay/releases)查找 `DashPlay-android-<版本>.apk`，按 APK 的安卓版本判断，不把日期版或没有 Android 资产的条目当成安卓更新；不能只检查 latest 页面就断言没有 APK。手机与盒子使用同一包。
- 核对目标设备、系统 ABI（不能只看芯片位数）、现有配置，以及发布页实际 Android 资产、版本、签名和 SHA-256。当前候选支持 ARMv7/ARM64；包内必须有匹配原生库，安装 ABI 不兼容不会由 JPEG 回退解决。没有 APK 就说明，可等待或由用户明确选择源码构建；OpenWrt `.apk` 不能装到 Android。
- 已安装优先同签名覆盖并保留数据，签名不兼容先说明迁移限制，不直接卸载/清数据。确认实际运行版本，不只看安装命令退出码；不主动替换用户正在测试的包。
- 已有 ADB 才使用，且多设备时明确序列号；重启后重查目标/IP。没有时返回可用本机或网页入口，不展开如何获得 ADB。
- 普通 shell、ADB root、App Root 分别记录。`rootUsable` 只表示 App 可执行 su 的候选条件，功能运行成功才算获权生效。只有 shell 能用的 su 不能交付 App 特权能力；Root 管理器存在时仍需允许 DashPlay。

## 按分支配置

遵照 [Q1–Q16](references/capability-routing.md#一题怎样带出下一题)，本节只补执行边界：

- 设备形态 → 车型 → 车机网络 → 网络来源/就绪 → 适用时 HTTP/HTTPS 路线 → iPhone 连接 → 接收端外网/USB 授权 → 适用时车机联网保持 → 适用时 HTTPS/DNS → 无线参数 → 身份/声音 → 适用时 HTTP 实车验证 → 启动方式 → 总结。
- 外部无线网络在 Q12 选择当前或其他 Wi-Fi；保存后重试不重复询问。当前名称不可读时可在 App 中按需允许读取，或手动填写；不要用 ADB 代授系统权限。只能复用该网络已保存的密码，不能把其他网络密码直接带入。建议 5 GHz Wi-Fi。邀请前发现实际网络与配置不一致，应提示修改网络设置，不发送旧参数。
- 有线也需要浏览器到接收端的局域网。两套 Wi-Fi 参数分别保存；外部参数用于无线邀请，不代替系统加入 Wi-Fi。
- 没有系统热点入口不等于没有服务，但 ADB 临时试开的热点不算产品入口。当前向导不教隐藏服务命令；缺可持续热点路径时解释并选择外部网络。
- 特斯拉先选择 HTTP 或 HTTPS：HTTP 兼容方式不要求 Root、域名或证书，本机热点需 VPN 地址验证，外部网络使用实际 LAN 地址；HTTPS 方式需本机热点 App Root 地址功能或外部网络已有的可访问地址，再检查 DNS 和可信证书。两种方式都要验证车机能保持 Wi-Fi 连接并正常显示画面。
- HTTP 优先使用 WebRTC 视频，连接失败时改用 JPEG 图片。JPEG 最大边不超过 1280 像素，实际清晰度和流畅度受设备性能影响；WebRTC 的效果取决于设备、浏览器和网络。不能由 HTTP 无 WebCodecs 推断 RTC 无硬件解码，也不能把所有卡顿归为正常情况。先核对实际安装版本，再分别验证访问地址、画面、触控及 USB 共存；本机验证不代替实车验证。
- 分别判断接收端与车机的互联网和 DNS 能力。车机使用外部网络时，接收端选择暂不上网，不应阻止车机使用已配置的公共 DNS。只有选择本机无互联网热点，或车机已确认无法联网查询时，才提示使用本地解析或返回修改网络条件。公共 DNS 记录仍须指向车机可以访问的地址。
- 安卓手机的 USB 上网是独立可选功能，默认关闭，旧有线设置不自动启用；不得把它作为无线配对前置条件。安卓盒子首次安装默认选择通过数据线使用 iPhone 网络；已有明确关闭的设置保持不变；用户在 Q7 改为其他来源时更新使用 iPhone 网络意图。数据线授权仍单独完成，拒绝时标等待。无线也可选 USB 只使用 iPhone 网络，不将插线等同切换会话。
- 特权功能只按所选分支授权：本机特斯拉地址、热点 DNS、USB 热点共享等。管理网页发起配对的 Root 自动确认路径不是免权限承诺；无 Root 时用设备本机确认。不给所有用户统一要求 Root。
- 总结须区别“接收端上网”和“车机上网”；自动观察、用户确认、实际通过分别记录。本机入口或当前路线所需证书未配好时继续对应功能页，不记初设完成。

## 验收及日常启动

仅在用户授权安装/测试、且所需条件具备时做验收；用户只要配置规则时不擅自延长成全项目优化。

测试同一台 iPhone 时先检查是否有其他 DashPlay 接收端运行；需要单接收端验收时让用户停止其他接收服务，关闭浏览器页面不能代替此操作。反复重连应对照各接收端的邀请时间，不直接归因于当前 APK 或数据线。用户明确略过已测项目时保留原版本证据和本轮边界。

1. 先按设备类别选测试路径：安卓手机断开与 iPhone 的数据线，由用户完成蓝牙配对，检查无线画面/声音，然后测安卓接收手机锁屏与解锁、后台恢复；不再安排手机有线拔插。安卓盒子按用户所选有线/无线测试。用户连接 iPhone、确认实际系统提示。观察 USB 枚举/授权或蓝牙配对、会话视频；浏览器画面和触控的实际效果由用户确认，端口可访问不代表画面已显示。
2. 分别验证盒子联网、热点客户端联网、车机联网保持、DNS、HTTPS 和声音出口。特斯拉导航、行车媒体限制未联合实测，不因开关值或音频能力条数就记通过。
3. 用户真断电再上电。AI 只读观察，不手工启动应用、点授权或补系统规则。盒子模式还检查前台；手机检查后台服务。ADB 整机重启不能代替真断电。
4. 盒子有线模式记录先开后插；按适用路径分别记录网络晚到、使用 iPhone 网络关闭记忆、覆盖升级。没有备用设备或车机条件时，保留未测项，不清主设备配置来凑新装测试。

`BootReceiver` 的前台恢复受 Android/ROM 限制；若需要设备专属启动能力，只说明缺口和可选设备，不在首次设置中展开系统改造。Android 首次解锁、热点重建、应用 Root 都不能被“有 ADB”代替。冷启动权限问题按需查 [USB 冷启动排查](references/usb-coldboot.md)。

完整安装验收需要持续使用时，按 [约半小时性能验收](references/performance-review.md) 让用户实际使用、AI 分析日志；不套用固定卸载清单或自动执行刷机/Root 修补。系统改动、安装范围和用户本轮限制始终优先。

交付只列：设备/ROM/APK、当前选择与访问方式、实际通过、待授权/待测试，以及下一项需要用户做的具体动作。源码编译、模拟器、真实盒子和实车分别记录；向导做完不等于可发布。
