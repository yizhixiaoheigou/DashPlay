# DashPlay 安卓版使用说明

**2026-11-04 产品范围调整：安卓手机仅支持无线 CarPlay；安卓盒子保留有线、无线与自动选择，仍受实际硬件条件限制。旧手机有线/自动配置升级时保存为无线；身份、配对和网络凭据保留。USB 上网是独立可选功能，手机默认关闭，不承载 CarPlay，也不沿用旧有线配置自动启用。**

安卓手机或电视盒子接收 iPhone CarPlay，车机浏览器通过局域网显示画面。两种设备使用同一 APK，最低支持 Android 5.0；USB、蓝牙、热点和视频传输仍需设备具备相应能力。本文描述当前开发版本的功能；可安装版本以发布页实际提供的 Android APK 为准，本地测试不代表所有设备和车机均已验证。

## 下载与升级

产品名为 **DashPlay for Android**，安卓手机与安卓盒子共用一个 APK。在 [DashPlay 发布列表](https://github.com/yizhixiaoheigou/DashPlay/releases)查找 `DashPlay-android-<版本>.apk`，按安卓版本选择；不要将 Linux/OpenWrt 的日期版本当作安卓版本，也不要下载安装 OpenWrt 的 `.apk`。当前 APK 包含 ARMv7/ARM64 原生库，需匹配设备系统 ABI，不支持 x86。

核对该发布条目的版本、SHA-256 和签名说明。手机可下载后通过系统安装器安装；盒子使用已有本机安装入口或已授权 ADB。没有实际 APK 时等待发布，或明确选择源码构建，不必默认自行编译。

已有安装可在 App 的「版本与更新」检查更新，或手动选择下载的 APK；最终安装由 Android 系统确认。覆盖升级要求同包名、兼容签名及允许的版本。beta 当前使用测试签名，未来正式密钥迁移须按届时说明处理，不能承诺跨签名覆盖；不要为绕过校验直接卸载或清数据。安装后核对实际版本、配置与连接恢复。

## 先准备能操作盒子的入口

使用项目实际提供的 Android APK，核对版本、签名和摘要。OpenWrt 的 `.apk` 不能装在 Android 上。覆盖升级需要相同签名；不兼容时先处理迁移，不直接卸载或清数据。

有屏幕/遥控器就打开 App。App 已运行且连入可互访网络，可在实际 HTTP 地址的 `/manage` 设置（默认 `http://设备地址:18743/manage`，请保留 `http://` 前缀）；已有授权 ADB 也可辅助。三者都没有，就需要先自行准备安装、启动及本机授权入口。网页不能替代 USB/VPN/Root 的系统弹窗。

不要求所有人准备 Root 或 ADB。这里仅说明所选功能需要哪些能力，不指导刷机、获得 ADB 或 Root；需要时请自行找教程，或换一条路线。

## 一步接一步设置

1. 选手机/盒子、普通浏览器/特斯拉。安卓手机仅提供无线；安卓盒子按硬件条件提供有线、无线与自动。设备类型也决定界面和启动方式，但不赋予 Root 等权限。
2. 选车机连接的网络：安卓本机热点、外部路由器/手机热点，安卓盒子还可选普通车机自己的热点。外部网络再问由谁提供；如果就是运行 CarPlay 的 iPhone，当前仅安卓盒子支持此组合并使用有线。安卓手机须改用本机热点或其他设备提供的网络。
3. 确认车机与盒子能互访。没有本机热点入口可换外部网络；没有局域网时，插 USB 也不能让车机访问盒子。
4. 特斯拉选择 **HTTP 兼容方式（实验性功能）** 或 **HTTPS 方式**。HTTP 不要求域名、证书或修改上游 DNS；本机热点需授权 VPN 并验证访问地址，外部网络使用接收端的实际局域网地址。HTTPS 本机热点需 App Root，外部网络需已有车机可访问的地址或转发；随后配置证书和域名解析。
5. 安卓手机固定无线，完成经典蓝牙配对及 Wi-Fi 设置；没有蓝牙则当前设备无法使用 CarPlay。安卓盒子可选有线/无线/自动：有线需要 USB Host/数据线，不依赖蓝牙。蓝牙关闭、未授权与无硬件分别提示，不需要用户猜。
6. 选盒子上网来源：已有 Wi-Fi/以太网/蜂窝、通过数据线使用 iPhone 网络、只用局域网。使用 USB 时完成本机 USB/VPN 授权及 iPhone 正常确认；使用 iPhone 网络可能使用手机流量。拒绝时保留等待，不当作已成功。
7. 特斯拉还要确认怎样保持 Wi-Fi：车机有真实外网、适用的 HTTPS 本机 Root 离线检查，或已有实测的离线保持方式。盒子有网不等于车机有网，HTTP 也不自动解决无网热点保持。
8. HTTPS 方式选择证书和域名解析。特斯拉需车机信任的域名证书；普通浏览器实际允许时可使用本地证书。公共 DNS 需车机能够查询，且记录已指向可访问的接收端地址；否则需本地解析。盒子不上网不等于外部网络中的车机不能查询 DNS。HTTP 画面跳过这两题，管理页始终使用 HTTP，不依赖证书。
9. 无线连接使用外部网络时，先选“使用当前 Wi-Fi”或“其他 Wi-Fi”。能读取当前网络名称时会自动填写；该网络已有保存的密码可直接使用，否则请填写密码。建议使用 5 GHz Wi-Fi。名称无法读取时，可按提示允许读取或手动填写。更换网络不会沿用旧网络的密码；实际网络与配置不一致时会提示修改并暂停邀请。本机/外部两套参数分别保存，不替代 Android 系统加入 Wi-Fi。然后导入自己的 CarPlay 身份、选择声音期望出口。
10. HTTP 方式进入“配置访问入口”：应用前面的选择，本机热点按需允许 VPN，然后启用服务。需要无线连接时可在这一步添加 iPhone。车机打开显示的完整 `http://…:端口/` 地址，确认画面和触控后继续。仅本机地址建立或页面端口可用，不代表车机已能正常使用。
11. 选每次手动开启，或启用 App 开机启动。自动启动仍须验证热点恢复、系统后台限制和首次解锁；不能凭开关保证上电即显示画面。
12. 检查总结，完成缺失的授权/功能页。保存配置、功能就绪、车机实测是三个状态，分别记录。

条件不足可返回改选或保存草稿；更改网络/路线会重新问相关确认，保留 Wi-Fi 参数。系统授权、导入身份、启用入口等操作会即时生效，草稿不是撤销这些操作。完整分支表、思维导图和能力要求见 [逐题设置规则](../skills/dashplay-android-install/references/capability-routing.md)。浏览器管理仍是表单，AI 可用 [安装 Skill](../skills/dashplay-android-install/SKILL.md) 按同一顺序引导。

## 无 Root 时怎么选

| 条件 | 选择与限制 |
|---|---|
| 普通浏览器 + 可互访网络 | 普通 CarPlay 不要求 Root；仍需所选 USB/蓝牙/浏览器能力 |
| 特斯拉 + 当前 APK 支持 HTTP + 可互访网络 | 可选择 HTTP 兼容方式；本机热点需 VPN 地址验证，外部网络使用实际 LAN 地址。还需确认车机保持 Wi-Fi 连接并正常显示画面 |
| 特斯拉 + 普通不可改的 iPhone/安卓热点或路由器 | HTTP 是可测试候选，无需改上游 DNS；客户端隔离/路由/ROM 差异仍可能失败，不能承诺所有组合 |
| 特斯拉 HTTPS + 本机热点 | 需 App Root 地址功能、可信证书、解析及保持连接方案 |
| 特斯拉 HTTPS + 安卓无 Root | 上游须已提供可达地址/转发；只拿到域名和证书不能补齐地址路径 |
| 电脑 ADB 是 root，App 不能调用 su | 不算 App Root；仍可尝试免 Root HTTP，不能据此启用 App 的 Root 功能 |

HTTP 画面优先 WebRTC，失败回退 JPEG；这是媒体传输选择，不会创造缺失网络或自动解除隔离。HTTP 管理页不受画面开关影响，证书未配置或失效时仍可访问。启用此免 Root 路线会停用 DashPlay 的 Root 地址/离线检查，避免地址争用；原有证书保留。

`100.96.0.1` 不是公网地址，也不是必须改成的路由器网关。手机运营商出口不自动转到盒子。证书申请/续期需联网，有效证书可离线使用，但 HTTPS 离线仍需解析、正确时间和客户端信任；HTTP 画面不需要这些证书条件。

### 输入访问地址

HTTP 和 HTTPS 共用一个网页端口，默认 **18743**。请按 App 显示的完整地址输入，注意开头是 `http://` 还是 `https://`，不要省略或替换。优先使用复制按钮或二维码，避免浏览器自动补成另一种协议。

- HTTP 画面地址：`http://设备地址:18743/`，需先启用 HTTP。
- HTTPS 画面地址：`https://设备地址或域名:18743/`。
- 管理地址：`http://设备地址:18743/manage`，请保留 HTTP 前缀，不要改成 HTTPS。

以上是格式示例，设备地址和自定义端口以 App 显示为准。统一端口不会取消 HTTPS 的证书要求。旧版默认 8080/8081 升级为 18743；旧版自定义的 HTTP 端口会保留并用于两种协议。更改端口后，原地址停止服务，需更新浏览器书签。

### 特斯拉的 HTTP 兼容页面（实验性功能）

当前实现提供一个可选入口：在「特斯拉访问入口」页打开 **HTTP 兼容入口**（本机热点测试 VPN 地址，外部热点使用实际 LAN 地址），车机用 `http://` 打开一个页面，不要求 Root、域名或证书。

使用前需确认以下条件：

- **画面传输方式**。优先使用 WebRTC 视频，连接失败时自动改用 JPEG 图片。JPEG 最大边不超过 1280 像素，并按窗口比例调整；实际清晰度和流畅度受设备性能影响。WebRTC 的效果取决于设备、浏览器和网络，不因使用 HTTP 就一定低于 HTTPS。出现持续卡顿、黑屏或触控异常时仍需检查原因。
- **画面与管理分开**。HTTP 页面用于显示和操作 CarPlay；设置、身份导入、证书和更新使用同端口的 HTTP 管理页面，不依赖 HTTPS 证书。
- **不加密**。只在你自己可信的局域网里用，请勿在此页面输入密码。
- **声音出口说明**。特斯拉模式下音乐、通话与 Siri 仍走车机蓝牙；导航播报和网页声音按声音设置与实车听音确认。
- **端口可能被拒**。没有 Root 只能用 1024 以上的端口（默认 18743），部分车机可能只接受默认端口，需在实车上验证。

同一个页面里还有 **打开地址测试**：先验证「车机能不能访问这台设备上的地址」，再去开兼容入口。先断开 USB CarPlay、关闭 HTTP 和 Root 地址，再开始独立测试；测试页保持到停止或离开。测试页只有一串随机标记，只有**另一台设备**（车机或另一台手机）连上盒子热点后能打开、看到同一串标记，并填回本机测试入口，才算通过。只在盒子自己身上能打开不算数。这一步不通过，当前网络的 VPN 地址路线尚不可用；需要检查网络条件或改选已有可达路径。普通外部热点没有通往虚拟地址的路由，打开 HTTP 不会改变这一点。

## 使用与验收

同一台 iPhone 使用一个接收端时，先停止其他 DashPlay 设备的接收服务。两个已配对接收端同时自动邀请可能反复争用连接；仅关闭另一端浏览器页面不等于停止其接收服务。发生反复重连时先核对是否有其他接收端仍在运行，再分析当前链路。

安卓手机使用无线 CarPlay：旧版保存的有线/自动设置会改存为无线，原有身份、配对及 Wi-Fi 参数保留。USB 上网默认关闭，需主动在「USB 上网（可选）」中启用，不能切换为有线 CarPlay。

安卓盒子有 USB Host 时新装预选有线，使用 iPhone 网络缺键预选开启；向导选择其他上网来源会关闭该意图，明确关闭值会保留。盒子关闭借网仍可用有线 CarPlay；活动无线会话插线与主动切到有线是不同动作。

手机无线测试顺序：先断开 iPhone 与安卓手机之间的数据线 → 核对蓝牙和网络 → 添加 iPhone 并确认配对码 → 确认无线画面、触控与声音 → 再测安卓手机锁屏、解锁及后台恢复。无线配对由用户在两台设备上确认；不再要求手机完成有线拔插测试。

先验证画面/触控及声音，再测脱离电脑真断电、先开后插、设备启动后才连接网络、关闭记忆和覆盖升级。盒子 USB VPN 能上网不代表热点客户端有网；本 App 的 USB 热点共享需另有 App Root/许可和实际转发验证。

你操作 iPhone、车机、连接切换和听音，AI 检查授权范围内的日志。特斯拉导航出口和行车媒体限制保持待联合验证，不根据开关文案认定已解决。没有备用设备时保留新装授权链未测，不清主盒子。向导完成不等于 APK 已达到发布标准。
