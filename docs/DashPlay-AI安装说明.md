# DashPlay（玩客云 / 斐讯 N1）：给 AI 助手的安装说明

把这份说明交给你的 AI 助手（能执行终端命令的那种），再告诉它：盒子的地址、认证文件在你电脑上的位置。它照下面做即可。

## 背景

DashPlay 是刷在玩客云或斐讯 N1 上的 CarPlay 接收盒：iPhone 用数据线插盒子（有线）或经蓝牙引导连 Wi-Fi（无线），车机浏览器打开盒子的网页显示 CarPlay。固件不含 CarPlay 认证文件（MFi 身份），要放入两个文件：`identity.pk8`（私钥）和 `certificate.p7b`（证书）。用户有就用用户的；没有就按第 2 节从 DiPlay 的发布包里取。

先确认车机有浏览器且能连 WiFi。N1 / 玩客云先问「车机能自己开热点吗」，不能时再问「有没有随身 WiFi」，从方式一（车机热点）、方式二（随身 WiFi）、方式三（盒子热点）三选一；特斯拉模式叠加于方式二或三，方式一不适用。F50 / OpenWrt 自己提供热点，是否上网取决于 SIM/WAN，不选这三种方式，特斯拉开关在 LuCI「车」。先按 Skill 一次一问、总结确认，再配置。从出厂刷机、下载摘要、升级和逐步失败退路以 [装机 skill](../skills/dashplay-install/SKILL.md) 为准。

N1 从原系统开始安装时，沿用用户已说明的已有 Linux / 原厂 ≤2.19 / 原厂 >2.19 起点，不重复问系统类型；只补齐缺少的版本或连接信息。两条原厂路线来自公开实践，本项目尚未实测。完整前置操作见装机 Skill 的 N1 第 3 步。

## 1. 连上盒子

- 电脑和盒子在同一个网络：
  - 盒子自己的热点 `DashPlay`（首次设置前不设密码），盒子地址 `192.168.78.1`；
  - 或者车机热点，盒子地址在手机浏览器打开 `http://dashplay.local/` 的设置页里能看到；
  - 或者用网线把盒子接到路由器，在路由器里查地址。
- SSH 登录：用户名 `root`，密码 `1234`。

```sh
ssh root@<盒子地址>
```

## 2. 放入认证文件

用户没有这两个文件时，从 [DiPlay](https://github.com/shihabal3amri/DiPlay)（另一个开源 CarPlay 接收端，PlayPort 的 README 也这样指引）发布的安卓安装包里取：包里 `assets/offline-mfi/` 下就是这两个文件。动手前先跟用户说一句：这是从 Carlinkit 盒子固件里公开出来、很多人共用的实验身份，不是专门发给 DashPlay 的，苹果哪次更新 iOS 都可能让它失效；只供自己用，不要转发、不要上传。

```sh
# DiPlay 的发布都标为预发布，所以从发布列表里取最新一个安装包，不写死版本
url=$(curl -s https://api.github.com/repos/shihabal3amri/DiPlay/releases | grep -o 'https://[^"]*/releases/download/[^"]*/DiPlay-[0-9.]*\.apk' | head -1)
echo "$url"
curl -L -o DiPlay.apk "$url"
mkdir -p offline-mfi && unzip -o -j DiPlay.apk 'assets/offline-mfi/*' -d offline-mfi   # Windows：tar -xf DiPlay.apk assets/offline-mfi
cd offline-mfi   # Windows 解出来在 assets/offline-mfi 下
```

最新一个包里没有 `assets/offline-mfi/` 时，换发布列表里的上一个版本再试。下面照常放入、核对配对；电脑副本留在用户指定的私有目录，未经授权不删除；完整下载校验与不会误判空输出的身份核对命令见 [装机 skill](../skills/dashplay-install/SKILL.md#放认证文件所有设备)。

```sh
scp identity.pk8 certificate.p7b root@<盒子地址>:/opt/dashplay/identity/offline-mfi/
ssh root@<盒子地址> 'chmod 600 /opt/dashplay/identity/offline-mfi/*'
```

检查私钥和证书是否配对：执行 [装机 skill 的身份核对步骤](../skills/dashplay-install/SKILL.md#放认证文件所有设备)，逐条检查 OpenSSL 退出码，比较非空公钥 DER；只有输出 `IDENTITY_MATCH` 才通过。不能比较失败管道的空输出，也不要打印私钥。

不配对时停下，告诉用户这两个文件不是一套。文件放好后约 2 秒盒子自动重启服务，不需要手动重启。

## 3. 确认在工作

```sh
ssh root@<盒子地址> 'systemctl is-active dashplay; journalctl -u dashplay -n 20 -o cat'
```

- 看到 `MFi identity missing` 说明文件没放对（路径或文件名）。
- 盒子设置页（`http://<盒子地址>/`）顶部不再提示“还缺 CarPlay 认证文件”。
- 已添加的 iPhone 打开蓝牙和 Wi-Fi 后，日志里出现 `CarPlay is live`。
- 还没添加 iPhone 时，让用户按设置页「添加 iPhone」操作（要在车机或另一台设备的浏览器里操作，iPhone 停在蓝牙设置页）。

## 4. 车机浏览器打不开时

先问清楚**车机屏幕上看到的是什么**，再按下表处理。设置页里这几项都在「自己的网址」分组（OpenWrt 在后台「服务 → DashPlay → 自己的网址」标签）。一般用不到，按顺序只做需要的那一步。

| 车机看到的 | 原因 | 怎么办 |
|---|---|---|
| 「无法访问此网站」，手机也打不开 | 地址变了或没连同一个热点 | 见下面「地址变了」 |
| 「您的连接不是私密连接」，有「高级 → 继续前往」 | 盒子用自己签的证书 | 点继续即可，正常现象 |
| 证书警告，**没有**继续选项（如 `NET::ERR_CERT_AUTHORITY_INVALID`） | 车机浏览器不让跳过自签证书 | ① 装盒子 CA 证书；② 车机不让装，就设置「自己的域名」 |
| 手机能打开同一地址，车机提示无法访问或被拦截，地址是 `192.168.x.x` | 车机浏览器不让打开局域网地址 | 「自己的域名」并勾选「同时登记公网 IPv6」（只适用于方式一、二）；OpenWrt 把「访问名称指向公网 IPv6」选「同时」 |
| 特斯拉 | 浏览器拒绝任何局域网地址，用名称也不行，也不走 IPv6 | 打开「特斯拉模式」（OpenWrt 后台「车」；玩客云 / N1 设置页，见下） |
| 别的车：局域网地址和指向它的名称都打不开，也不走 IPv6 | 车机浏览器拒绝任何局域网地址 | OpenWrt 勾选「车机不让开任何局域网地址」（见下） |

### 地址变了

方式一、二里盒子的地址由车机热点或随身 WiFi 分配，盒子会请求沿用上次的地址，但不保证。手机连同一个热点后打开 `http://dashplay.local/`，设置页「CarPlay 画面」里是当前地址；也可以在车机热点或随身 WiFi 的已连接设备列表里找 `DashPlay`。方式三的地址固定为 `https://192.168.78.1:18443/`。车机和盒子要连在同一个热点上；方式三要让车机连盒子热点 `DashPlay`。

### 装盒子 CA 证书

设置页「自己的网址 → 下载盒子 CA 证书」，把 `dashplay-ca.crt` 装进车机系统的受信任证书（车机支持时）。盒子证书会随地址变化自动重签，装过一次 CA 后不再提示。

### 自己的域名（DuckDNS + 免费正式证书）

1. 用户在 duckdns.org 免费注册，建一个子域名（如 `mycar`），记下页面上的 token。**token 只让用户自己在设置页输入**，不要写进对话、文件或日志。
2. 设置页「自己的网址」填子域名和 token，保存；OpenWrt 在后台「服务 → DashPlay → 自己的网址」填「自己的域名」和「DuckDNS token」。
3. 盒子把 `子域名.duckdns.org` 的公网解析指向车机访问它的地址（方式一、二是盒子在热点里的地址，变了自动改；方式三默认 192.168.78.1，特斯拉用设置页显示的共享地址（默认 100.96.0.1）；OpenWrt 是路由器地址），并用内置的 acme.sh 向 Let's Encrypt 申请免费正式证书（DNS 验证，不需要开放端口），到期前 30 天自动续签。设置页这一项会显示进度和有效期。
4. 证书申请到后**下次开机**启用，之后车机打开 `https://子域名.duckdns.org:18443/`（设置页「CarPlay 画面」会把它排在第一个）。

- 申请和续签要盒子能上网：方式一、二在车上就有网；方式三推荐在家插上网线开机申请与续签。盒子先确认有默认路由、DuckDNS 和 Let's Encrypt 都能解析才发起申请；没网时只等不罚，失败后约 1 分钟起自动重试（60/120/300/900 秒，之后每小时），设置页可以点「重新申请证书」立即再试一次。日志里看 `duckdns ... OK` 和 `certificate for ... installed`；acme.sh 的详细输出在 `/opt/dashplay/state/acme/acme.log`（0600，可能含账号信息，不要整段贴出），上一轮的留在 `acme.log.1`。
- 先确认这条路对这台车机有用：只填好域名、等解析生效后，在车机打开 `https://子域名.duckdns.org:18443/`。如果出现的仍是证书警告，说明车机接受这个域名，等证书即可；如果是「无法访问」或被拦截，多半是车机或它用的 DNS 不接受指向局域网地址的域名（有的路由器、随身 WiFi 有「DNS 重绑定保护」），这时再勾选下面的「同时登记公网 IPv6」。
- 已有别处申请好的证书（含完整链）时，可以在设置页「自己的域名 → 手动导入证书」粘贴 `fullchain.pem` 和 `key.pem` 两段 PEM，点「导入并重启服务」。设置页会检查证书属于这个子域名、公私钥成对、已经生效且剩余有效期超过一天；不通过会保留原证书，不会重启服务。也可以自行检查后直接放进 `/opt/dashplay/state/tls/own/fullchain.pem` 与 `key.pem`（目录 0700、私钥 0600），重启服务后生效。它过期前一天自动退回盒子自带证书；这种方式需要自己按时更换。

### 同时登记公网 IPv6（车机不让打开局域网地址时）

- **用途**：有的车机浏览器拒绝打开 `192.168.x.x` 这类局域网地址。勾选后，盒子把自己的公网 IPv6 地址也登记到「自己的域名」：车机拿到的是公网地址，但这个地址就是同一个 WiFi 里的盒子，画面仍在 WiFi 里直接传，不经过外网、不耗流量。
- **条件**：只适用于方式一、二（盒子连车机热点或随身 WiFi），且这个热点要给设备分配 IPv6；方式三盒子热点不连外网，没有公网地址。要先设置好「自己的域名」，勾选框在同一个表单里。
- **安全**：这个地址登记在公开的 DuckDNS 上，谁都能查到，所以盒子同时启用 IPv6 防火墙，只让同一个 WiFi（同一网段前缀）和链路本地地址的设备连进盒子，外网连不进来（包括 SSH）。防火墙启用不了时盒子不会登记这个地址，设置页会说明。热点重新拨号换了地址，盒子一分钟内跟着改。
- **检查**：设置页这一项显示「公网 IPv6 … 已登记」才算生效；「没有给盒子分配公网 IPv6」说明热点不给 IPv6，这个办法用不了。在盒子上 `ip -6 addr show scope global` 能看到地址，`nft list table inet dashplay_v6` 能看到防火墙规则。
- **OpenWrt 路由器**做法不同、也更简单：路由器自己回答这个名字，地址不公开，也不需要额外防火墙（OpenWrt 自带）。在「访问名称指向公网 IPv6」选「同时」；「只用」只用来确认这条路是否通。

### 特斯拉模式（OpenWrt）

- **先问 SIM/WAN**：F50 有 SIM 且能上网时维持正常 DNS/DHCP；无卡或无信号时，「车机上网」的默认自动模式启用方案 A，恢复上游后还原。可关闭代答；开启时仍只在无上游时回答，首次启用会让 WiFi 重连。无卡 A 本轮已实现，待实测，不能用 10-14 插卡通过代替。
- **F50 不支持借手机热点的 B**：当前驱动不能同时当热点和连接另一热点；要让特斯拉自带音乐/地图联网，给 F50 插 SIM。A 下 CarPlay 正常，自带应用不能联网。普通 OpenWrt 以实际 WAN 为准。

- **打开**：后台「服务 → DashPlay → 车」勾选「特斯拉模式」，保存并应用（命令：`uci set dashplay.main.tesla_mode=1; uci commit dashplay; /etc/init.d/dashplay restart`）。它等于一起打开下面的「车机不让开任何局域网地址」（网段改成 `100.96.0.1/24`）、让声音默认走车机蓝牙，再加特斯拉浏览器专用的全屏；那几项不用另外勾。声音仍可在「声音」里单独调整。
- **分工**：iPhone 用蓝牙连特斯拉，并在特斯拉里把媒体来源选成这部 iPhone：音乐、电话、Siri 都走特斯拉蓝牙（方向盘、媒体卡片、音量、车上麦克风和回声消除都是特斯拉原生的）；CarPlay 网页负责画面、触控和导航播报（播报放大 3 倍）。要让声音回到网页，把「声音」里的「声音输出」设为「留在 CarPlay」。细节见下面「声音输出」。
- **全屏**：特斯拉浏览器不理网页自己的全屏；点 CarPlay 网页右上角的全屏，会经腾讯视频、1905 电影网的跳转页回到本页并去掉地址栏（腾讯那页点「前往 电影网」）。
- **特斯拉 WiFi 必须打开「行驶中保持连接」**：否则特斯拉一出 P 挡（倒车、开车）就断开 WiFi，画面中断到挂回 P 挡（2026-10-14 实测倒挡断 6 秒）。在特斯拉「控制 → WiFi」点所连热点的设置打开（英文 Remain connected in Drive）；打开后离开浏览器再回来 0.02 秒出画。
- **特斯拉搜不到 WiFi**：2026-10-14 实测特斯拉搜不到 5G 信道 36 的热点；在「网络 → 无线」把国家/地区设为中国、信道改为 149 后能连上（DashPlay 自动跟上新信道）。还不行就改 2.4G 信道 6。
- **实测（2026-10-14）**：画面跟手、声音从车上音响出；方向盘左滚轮左右拨、按下与媒体卡片在 iPhone 连特斯拉蓝牙后可用；倒挡或切到别的应用时特斯拉会冻住浏览器，回来后网页在原连接上接着（显示区域让切特斯拉自带全屏也不重连）。已知：Siri 用完音乐不会自动继续，按一下播放。
- **说明**：100.64.0.0/10 是运营商用的共享地址段（RFC 6598），借来当局域网用是为了绕开特斯拉对局域网地址的拦截；特斯拉哪次更新把这段也拦了，这个办法就失效。

### 特斯拉模式（玩客云 / N1）

- **设置**：首次设置先选车，再网络、上网、声音、iPhone，最后确认总结。以后用「车、网络、车机上网、iPhone、声音、自己的网址、远程调试」分组单改。约 1 分钟生效，期间 CarPlay 会断一下。旧的已完成设置不会被要求重走向导。
- **方式三**：车机连盒子热点，地址默认 `100.96.0.1`；别的接口占用时改用共享空间内备用 /24，以设置页地址为准。不会把 DuckDNS 改成特斯拉打不开的私网地址。
- **不上网（A）**：盒子回答特斯拉的四个联网检查名和自己的域名（方式三设了自己的域名时，非特斯拉车也默认由盒子回答，设置页「自己的域名」里可关）。特斯拉会接受热点，CarPlay 正常工作（画面和声音不耗流量，CarPlay 里的音乐、导航照常用 iPhone 自己的流量）；但特斯拉自带音乐、地图不能联网，它不会改走 4G DNS。N1 手工方案 2026-10-15 有线/无线实车通过，正式版本待复测。
- **借手机热点（B）**：在「车机上网」选借手机热点，输入名字和密码；开热点的可以是同一部 iPhone，也可以是另一部手机。手机必须一直开热点，车机自带应用上网用它的流量，CarPlay 画面和声音不耗流量。找不到、掉线或信道改变时自动退回 A，之后重试；切换会断一下，设置页显示状态。同一 iPhone 开热点可用有线或无线，10-15 无线在家通过，车机侧待复测；另一手机热点 + 无线、2.4 GHz 未实测。N1 手工 B 的有线已实测，正式版本待复测；玩客云未测。
- **方式二**：特斯拉不能用方式一。随身 WiFi 须允许把 LAN 改到 `100.96.0.1/24`；不能改就选方式三。车机访问盒子实际租约地址，不是随身 WiFi 的网关。该组合未实车验证。
- **自己的网址**：特斯拉推荐 DuckDNS + 正式证书，回家插网线申请，按期联网续签。只用 IP 时警告页有没有「继续」仍未实车验证。A 下盒子直接解析自己的域名，浏览器本地验证证书，不需要外网查名。
- **全屏与声音**：车上打开「行驶中保持连接」。声音默认车机蓝牙，可在「声音」单独调整。全屏跳转需要外网，A 下保留普通画面，B 下另做全屏验收。
- **远程调试**：需要已安装的 Tailscale（禁用其 netfilter 和 DNS 接管，避免拦共享地址）。设置页保存独立调试热点，可预填日常热点；开始后盒子暂时关自己的热点，只用有线，域名记录不改。**调试中想恢复：给盒子拔电再插上，就回到原来的网络；或等 30 分钟自动结束。** 能进入设置页也可点结束调试。
- **验收与排错**：A 要连接无提示、域名出画和触控；B 另加特斯拉自带网易云可用。各拔电重启、记录 MAC 与日志时刻。详情看 [Skill 排查表](../skills/dashplay-install/SKILL.md#特斯拉连-wifi-的排查表)，单测和模拟不能代替实车。

### 声音输出（所有盒子）

- **一个开关，两种取值**：「留在 CarPlay」或「不走 CarPlay」。设置页「声音」与 CarPlay 画面「盒子设置 → 声音」是同一个配置。
  - **留在 CarPlay**：接收端声明完整的 9 项音频能力。音乐、Siri 和通话从哪个设备出声，由 iPhone 控制中心决定（展开音乐播放卡片，点右上角输出图标）；导航播报留在网页，会放大 3 倍（网址加 `?promptgain=1..8` 可改）。
  - **不走 CarPlay**：接收端不声明音频能力；iPhone 认为 CarPlay 没有声音输出，所有声音（含导航播报）都由 iPhone 本身或它连着的蓝牙设备播放，网页没有声音。
- **特斯拉模式默认走车机蓝牙**：iPhone 先用蓝牙连车机，并在车机里把媒体来源选成这部 iPhone。
- **做法**：玩客云 / N1 在设置页「声音」保存（存在 `/opt/dashplay/state/options.json` 的 `audio_route_navigation`）；OpenWrt 在后台「服务 → DashPlay → 声音」选择（`uci set dashplay.main.audio_route_navigation=carplay` 或 `bluetooth`，再 `uci commit dashplay`）。改动几秒后 CarPlay 重连一下，WiFi 不断。
- **检查**：接收端命令行带 `--audio-routes`；选「不走 CarPlay」时 `/info` 只剩 6 项音频能力，iPhone 控制中心不再出现 CarPlay 输出。

### 车机不让开任何局域网地址（OpenWrt）

- **用途**：车机浏览器不让打开 `192.168.x.x`、`10.x.x.x`、`172.16–31.x.x` 这些局域网地址，用指向它们的名称（`dashplay.lan`、自己的域名）也不行，又不走 IPv6（上面的公网 IPv6 帮不上）时。`100.64.0.0–100.127.255.255` 这段地址不算局域网地址，特斯拉能打开（2026-10-14 实测）；特斯拉直接用上面的「特斯拉模式」。
- **做法**：后台「服务 → DashPlay → 自己的网址」勾选「车机不让开任何局域网地址」，保存并应用（打开「特斯拉模式」时这一项隐藏，特斯拉模式已包含它；打开特斯拉模式会把这一项清掉，关掉特斯拉模式就改回原来的地址）。DashPlay 把路由器自己 WiFi 所在的网络（通常是 `lan`）改成 `100.96.0.1/24`，原来的地址记在 `/opt/dashplay/state/lan-before.json`；访问名称、自己的域名和盒子证书自动跟着改。命令：`uci set dashplay.main.shared_lan=1 && uci commit dashplay && /etc/init.d/dashplay restart`。
- **改完**：车机和手机重新连一次 WiFi（拿到 `100.96.0.x`），后台改用 `http://100.96.0.1/` 打开；车机打开 `https://100.96.0.1:18443/`，设了自己的域名就打开 `https://子域名.duckdns.org:18443/`（不再有证书警告）。用 USB 连电脑管理的 F50，电脑那头的地址也变成 `100.96.0.x`。
- **限制**：只对路由器自己的 WiFi 有效（车机要连路由器的 WiFi）。路由器上别的网口已在用这段地址时不改，设置页会说明原因。网络不是单个静态 IPv4 地址（如手工配了多个地址）时也不改。
- **改回**：取消勾选并保存，DashPlay 把原来的地址放回去；如果这期间在后台手工改过地址，DashPlay 不动它。

## 常用位置

| 内容 | 位置 |
|---|---|
| 程序 | `/opt/dashplay` |
| 服务 | `systemctl status dashplay` |
| 认证文件 | `/opt/dashplay/identity/offline-mfi/` |
| 运行日志 | `/run/dashplay/`（`receiver.log` 为 CarPlay 接收端） |
| 设置页 | `http://<盒子地址>/` |
